# Contributing to AxiomNode Lab projects

Thanks for considering a contribution. Individual repositories may define stricter requirements; when they do, the repository-specific guidance takes precedence over this default.

## Before opening a pull request

1. Read the repository README, security notes, and open issues.
2. For a non-trivial feature, open or join an issue first so the problem and scope are clear.
3. Keep the change focused. Avoid unrelated formatting or refactors in the same pull request.
4. Add or update tests for changed behavior, including negative/failure cases when relevant.
5. Update documentation when the public API, setup, behavior, or limitations change.
6. Never commit credentials, private investigation data, personal data, or generated secrets.

## Pull requests

A useful pull request explains:

- the problem being solved
- the chosen approach
- important tradeoffs or security boundaries
- how the change was tested
- any manual verification still required

Security-sensitive changes should state both what the change protects against and what it does not guarantee.

## Quality expectations

We value readable code, reproducible tests, conservative security claims, clear failure behavior, and documentation that a new contributor can follow without private context.

Small fixes, regression tests, documentation improvements, and focused tooling improvements are all valid contributions.
